# Glossary

A comprehensive glossary of all terms used in the Ahmed Enterprise AI Workspace.

## Architecture Terms

| Term | Definition |
|------|------------|
| **8-Layer Architecture** | The workspace's layered structure: Personal, Professional, Domain, Quality, Security, Automation, Knowledge, Future |
| **Personal Layer** | Ahmed's engineering preferences and style choices that apply globally |
| **Professional Layer** | Universal engineering standards that apply to all projects |
| **Domain Layer** | Engineering domain knowledge in skills and agent expertise |
| **Quality Layer** | Testing, review, accessibility, and performance standards |
| **Security Layer** | Authentication, secrets management, and compliance rules |
| **Automation Layer** | Commands, workflows, and templates for common tasks |
| **Knowledge Layer** | Accumulated memory, decisions, and learnings |
| **Future Layer** | Experimental features and expansion hooks |

## Workspace Concepts

| Concept | Definition |
|---------|------------|
| **AGENTS.md** | Configuration file that defines workspace rules, routing, and instructions |
| **SKILL.md** | Skill definition file containing domain-specific instructions and workflows |
| **Domain Detection** | Automatic routing of tasks to appropriate agents based on file paths and keywords |
| **Skill Loading** | On-demand injection of domain knowledge when tasks match skill descriptions |
| **Knowledge Accumulation** | Process of recording patterns, decisions, and lessons over time |
| **Workspace Memory** | System for storing and retrieving accumulated workspace knowledge |
| **Workspace Metrics** | Tracking system for measuring workspace health and effectiveness |
| **Self-Improvement** | Automated analysis and optimization of workspace configuration |
| **Conflict Resolution** | Rules for handling disagreements between agents (security wins) |
| **Priority Hierarchy** | Order of precedence: security > build-breaking > user intent > auto-detection |

## Configuration Terms

| Term | Definition |
|------|------------|
| **Global Config** | Workspace configuration at `~/.config/opencode/` |
| **Project Config** | Project-specific configuration at `.opencode/` |
| **Config Priority** | Project config overrides global config overrides defaults |
| **Environment Variables** | Runtime configuration stored in `.env` files |
| **Manifest** | Complete inventory of workspace components and their relationships |
| **Dependency Graph** | Map of how agents, skills, and commands depend on each other |

## Engineering Terms

| Term | Definition |
|------|------------|
| **TypeScript Strict Mode** | TypeScript configuration with strict type checking enabled |
| **App Router** | Next.js routing system using the `app/` directory |
| **RTL-First** | Design approach that prioritizes right-to-left layout |
| **Bilingual** | Support for both Arabic and English content |
| **Mobile-First** | Responsive design approach starting with mobile layouts |
| **Dark Mode** | Class-based dark mode using Tailwind's `darkMode: "class"` |
| **Clean Architecture** | Architectural pattern with dependencies pointing inward |
| **Single Responsibility** | Principle that functions should do one thing well |
| **Composition over Inheritance** | Prefer combining small components over deep inheritance |
| **Fail Fast** | Pattern of throwing errors immediately on invalid input |
| **No `any`** | TypeScript rule禁止使用 `any` type |
| **ADR** | Architecture Decision Record — document for significant decisions |
